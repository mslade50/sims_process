1. Goal

Replace Kalshi's web UI with a private, always-on execution platform for golf outright markets — enter orders from anywhere, with an order-expiry/auto-kill workflow, plus a "ticker tape" of large trades. Hosted serverless on Cloudflare (no home-PC dependency), gated by a password.

2. Architecture

Two deployables sharing one D1 database. Cron Triggers don't run on Pages, and the password gate only needs to protect the user-facing app — hence the split.

PieceWhatNotes
app/ (Cloudflare Pages)Frontend (static) + /api/* Pages FunctionsProject kalshi-exec, prod branch main. Password-gated via functions/_middleware.ts.
cron/ (Worker)Internal scheduled() Workerkalshi-exec-cron. Minute job (trade poll + auto-kill) + weekly retention sweep. No user-facing surface (status fetch is read-only).
D1SQLite kalshi-execBinding DB. Tables: pending_kills, trades, collector_state, fills, settlements, proposals. (Last three NEW this session — create via schema.sql.)

Why this shape

  • Serverless beats the tunnel for this: no machine to keep awake, $0 hosting, and the Kalshi key lives as an encrypted secret (stronger than a .pem on a PC).
  • Validated up front with a throwaway smoke Worker: Kalshi does not geo-block Cloudflare egress (ran from US PoP "BOS"), and RSA-PSS signing ports cleanly to Web Crypto. Smoke Worker since deleted.
  • Auth is a self-hosted password gate, not Cloudflare Access email-PIN: the wrangler OAuth token lacks Zero Trust scopes, and creating Access requires dashboard work. Email-PIN remains a possible upgrade via a scoped CF API token.

5. Kalshi API contract (matched to kalshi_maker.py)

  • Base: https://api.elections.kalshi.com/trade-api/v2
  • Signing: message = timestampMs + METHOD + signPath; signPath includes /trade-api/v2, excludes the query string. RSA-PSS, SHA-256, saltLength 32. Headers KALSHI-ACCESS-KEY/TIMESTAMP/SIGNATURE.
  • Order body: {ticker, client_order_id:"exm"+uuid, type:"limit", action:"buy", side, count, <side>_price_dollars:"0.NNNN"}; for a kill, add time_in_force:"good_till_canceled" + expiration_ts (unix sec). Price uses the decimal-dollar field (handles deci-cent markets).
  • Trades feed fields (gotcha): count_fp, yes_price_dollars, no_price_dollars (decimal-dollar strings), created_time, taker_side, ticker, trade_id — NOT count/yes_price. Getting this wrong stored null/0 (fixed).

8. Retention & storage policy

  • Collector floor: MIN_TRADE_SIZE = 100 — sub-100 trades never written.
  • Working tape: all ≥100 kept 7 days.
  • Permanent archive: ≥ARCHIVE_THRESHOLD = 5000 kept forever.
  • Sweep: weekly cron deletes ts < now-7d AND count < 5000. First real deletions are 7+ days out.
  • Tuning: now [vars] in cron/wrangler.toml (MIN_TRADE_SIZE/RETENTION_DAYS/ARCHIVE_THRESHOLD) → edit + redeploy, no code change. Active values echoed in the status payload's config. 5000 was picked from ~15 min of peak final-round volume (~23k ≥100 trades, max single 188,305). Revisit after a real week of mixed data — likely wants to go higher.

9. Caveats / gotchas

  • shared key The maker bot and this platform use the same Kalshi key. The bot's --cancel-all cancels all resting orders incl. manual ones. (Manual orders use an exm… client_order_id so the bot's normal reconciliation ignores them — but cancel-all doesn't discriminate.)
  • test order No real order has been placed through /api/send yet. Place a tiny test (1 contract far from market), confirm, then cancel.
  • cron status public kalshi-exec-cron.workers.dev is publicly readable (counts only, no secrets/positions). Now lockable: set the STATUS_TOKEN secret to require ?token=.
  • The collector polls exchange-wide /markets/trades and filters to golf (cap 30 pages/run, logs if capped). Fine at current volume.
