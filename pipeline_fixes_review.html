The one-sentence summary: the scraper used to learn "which round to price" from the sim itself, which created a feedback loop that mispriced live rounds; we replaced that with a dead-simple day-of-week rule, hardened the odds guards on both consumers, fixed a 3-week-silent round-scores blackout, tightened over-loose name matching, wired the live-outrights page to our fair prices, and cut logging noise.

1 · The problem we hit

While pricing the US Open R3, the round simulation ignored the scraped sharp-book odds and fell back to DataGolf only. The scraped round_matchups file was stamped round: 2 while we were pricing R3, so the round guard correctly dropped it — but the file should have been R3. There was also a transient corrupt file (round:2, 0 matches, blank timestamp) during the round transition.

2 · Root cause (what the audits found)

Two multi-agent audits across both repos overturned the initial theory and found the real mechanisms:

2a · The round was sim-driven — a feedback loop

The live writer of round_matchups_latest.json is golf_scraping/board/build.py (the old sentinel.py is deprecated). It read the round verbatim from the sim's own sim_fairs.json["round"]:

round_sim.py → publish_sim_fairs.py → sim_fairs.json["round"] → board/build.py ↑ │ └────────────── odds_loader (reads the stamped round) ←─────────────┘

So if the sim hadn't advanced to R3 yet, the board stamped R2, filtered out the real R3 book rows, and the sim could never pick them up. A circular dependency that mispriced every round transition.

2b · Round scores had been silently blacked out for 3 weeks

FanDuel stopped posting the total-strokes round-score O/U market after 2026-05-30. The board's "keep-last-on-empty" logic never overwrote the file on an empty scrape, so round_scores_latest.json froze at the May-30 Charles Schwab snapshot — and no alert ever fired. (git-confirmed: last write 2026-05-30 while every other market kept updating.)

2c · Name matching was over-inclusive

names_match used a 2-character startswith prefix, so "si woo kim" matched "simon kim", and a single initial like "k lee" matched both "kevin lee" and "kyoung-hoon lee" — silently merging distinct players' odds, worst post-cut when the field shrinks. Plus the sim spammed a per-player "not found" Telegram blast dominated by missed-cut players.

3 · Your design decisions

DecisionChoice
Round verificationPure day-of-week — Thu→R2, Fri→R3, Sat→R4. No DataGolf, no sim. No override.
Round scoresFull restore + alert — source from any book (DraftKings fallback), explicit-empty when none, deduped blackout alert.
Live-outright fairsBook-aware dead-heat — WIN uses dead-heat for all books; top-5/10/20 use dead-heat for standard books but no-dead-heat for Kalshi & NoVig.

4 · Changes — golf_scraping (the scraper / board)

board/build.py — kill the feedback loop

WhatWhy
round_for_now() — ET weekday → round {Thu:2, Fri:3, Sat:4, Sun:4, Mon–Wed:1}; sim_round now comes from this, not sim_fairs.json.Breaks the circular dependency. Always a concrete int (never None), so the stamped round can't go missing. Anchored on ET because the Cloudflare cron fires Thursday-night runs on UTC-Friday — UTC anchoring would mis-round them.
Warns if the sim's published round disagrees with the DOW round.Diagnostic only — DOW always wins now.

board/build.py — round scores

WhatWhy
Source score_lines from every book's collected props (prop_type=='round_score'), event-scoped.DraftKings automatically backfills when FanDuel drops the market.
Dedicated writer: stamps round + event_name; when a round is live but no lines exist, writes an explicit empty file (never keep-last-stale).A stale cross-event score file can never silently feed the pricer again.
_round_score_blackout_alerted() → deduped Telegram alert (once per event/round/ET-day).You find out immediately next time a book drops the market, without 48 alerts/day from the 30-min loop.

Other scraper files

FileWhat & why
odds_loader.pyNew shared guard_scraped_data(): freshness → event_id → file-round → per-row filter. A missing top-level round on a round file is now treated as suspect and dropped. load_matchup_odds refactored to use it. One guard implementation the sim and odds screen both share, so they can't diverge.

The odds screen now trusts exactly what the sim trusts, and shows our fair prices with the correct dead-heat treatment per book.
round_sim.py(1) load_score_lines(sim_round) rejects a round-mismatched file. (2) Sheet-vs-DOW divergence warning (sheet still wins, so you can re-price past rounds). (3) Name-mismatch noise removed → one in-field-only summary that suppresses missed-cut players. Less noise, and the spam was dominated by un-actionable missed-cut names.
sheet_config.pyThe full config block prints once per process (a one-liner thereafter). Removed the duplicate config dump.

7 · Proven vs. live-only

Proven offline

Each test imported the real function and asserted on the change-under-test — not reimplementations.

  • DOW round contract (both repos)
  • The full guard matrix + missing-round drop
  • Name tightening + ambiguity handling
  • Round-scores 3-way write + blackout dedup
  • Book-aware DH / no-DH edge math
  • Score-line round guard, config dedup

Confirm on first live round

Inherent — fixtures can't fabricate live book data.

  • The board stamping real round/event_id on the actually-published JSON. Watch the first live run's logs for the guard messages.
  • The Kalshi overlay edge path — only runs when live Kalshi markets exist (the no-DH split was proven via the reachable DataGolf branch).

cd ~/Documents/golf_scraping
python -m py_compile board/build.py scrapers/fanduel.py utils/names.py utils/output.py

cd ~/Documents/golf_scraping && python -c "
from board.build import round_for_now

# sims: the shared guard drops a missing-round file
cd ~/Documents/sims_process && python -c "
