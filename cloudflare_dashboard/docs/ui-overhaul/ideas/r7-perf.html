R7 performance: what I would build with unlimited budget

  1. Server-render the view's first screen.Hypothesis: every LCP element is drawn after hydration; rendering the above-the-fold markup in the Worker from the inlined data moves LCP to roughly FCP (0.9 s). Build: render the golfer hero, This week header and Scoring headline to HTML in the Worker (RSC already available) and hydrate over it. Data: the inlined first-screen documents. Test: perf-check phone LCP and a hydration-mismatch test. Why: removes the shell as the LCP floor.
  2. Lazy below-the-fold golfer sections with reserved slots.Hypothesis: about 25 KB gz of the 56 KB golfer chunk is not needed for LCP. Build: lazy() PlayerDeepDive, FilteredPlayerShapes, PlayerDispersion, PlayingStyle in ChartSlot-style boxes of measured height. Test: golfer LCP, CLS, ui-check. Why: golfer is the slowest route.
  3. Slimmer client runtime.Hypothesis: react-server-dom client plus vinext navigation is about 100 KB gz that a mostly client-rendered dashboard barely uses. Build: a plain React entry (no RSC flight client) for pages that need no server components. Test: bundle budgets, full route sweep. Why: shell bytes are the floor on a 1.6 Mbps link.
  4. Priority-ordered delivery (HTTP/2 or 103 Early Hints).Hypothesis: the Worker can send Early Hints for the shell and view chunks before the HTML is ready. Build: 103 response in the Worker with the same Link list. Data: route-chunks.json. Test: WebPageTest on the real Cloudflare URL (the local preview is HTTP/1.1). Why: starts downloads 100-300 ms earlier on real devices.
  5. Real-device field data.Hypothesis: lab LCP and phone LCP differ. Build: a tiny web-vitals beacon to a Worker counter, owner-only. Test: a week of data by route. Why: confirms the 2.5 s bar where it matters.
