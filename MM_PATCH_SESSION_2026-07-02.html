2 · Today's near-miss (why the shrink guard exists)

Plan was to re-publish fairs from this box to stamp sim_run_at and clear the maker's HALT. The dry-run showed the payload this machine would build: winner-only (142 winner fairs, zero top_5/10/20/make_cut, zero matchups) — because yesterday's full R1 sim ran on the other machine, and this box only has simulated_probs.csv. Origin currently carries the full payload (5 outright markets, 10,296 matchups). Publishing would have stripped the board and maker down to winner markets, with a fresh stamp making it look healthy. The sim_run_at regress guard alone can't catch this (the local stamp was newer than origin's missing one) — hence the market-shrink guard, which now refuses exactly this publish.

Multi-machine reality check: the sim machine and the dev/maker machine are different boxes, and the stale OneDrive copy (~/OneDrive/sims_process, May-era) is a third. Every guard added today assumes any of them can try to publish. The rule the guards enforce: the machine with the freshest, fullest sim output wins; everyone else is refused loudly.
